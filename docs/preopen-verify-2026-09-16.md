## 監査との違い（読むときの注意）

- **S1** の「本番に該当データが実在」は 9/16 の注文のこと。厨房・レジは営業日（JST の日付）で絞るので、**9/17 の画面には出ない**。壊れ方そのものは毎日の会計済み注文で起きる。そして監査に無い重い問題が見つかった: 厨房の「すべて提供済みにする」は会計済み(paid)の注文まで served に書き戻し、**レジに未会計として復活する**（本番の取引内で確認）。
- **A4** の「初日は注文実績が無い＝守りが効かない」は誤り。検証注文が25件残っているので、ドリンク・アルコール・パンケーキ・サラダ・ハンバーガー・アサイーボウルの6カテゴリは DB が削除を止める。逆に言うと**検証注文を消すと守りが消える**。
- **P2** の「画面は自動で印刷されますと案内している」は、failed（失敗で固定）の伝票には当てはまらない文言（プリンタ停止時／要対応時の文）。監査の行番号 88/95 は 85/94 が正しい。
- **O3** は「古い価格」よりも重い。単価はお客様の端末が送った値をそのまま採用するので、1円で送っても通る（改ざんに無防備）。
- **A2** の「最高¥4,620」は商品価格。割引は1杯あたり最大¥200で、安いドリンクから順に埋まる。

## 人が決めること（選択肢つき）

### 1. セットドリンク割引をアルコールにも効かせるか（A2）
本番の設定は ON（9/15 に店舗が有効化）。対象は「区分がドリンク」のカテゴリー全部で、アルコールもドリンクのサブカテゴリーとして登録されているため対象になる。9/15 のテスト注文で既にグラス赤ワインに −¥200 が付いて会計されている。
組み合わせの条件: **フード1品につきドリンク1杯まで**、**単価の安いドリンクから**、1杯あたり **min(¥200, そのドリンクの単価)**。テイクアウトには効かない設定。
1. このまま（アルコールも対象）: 変更なし。
2. アルコールを除外: DB の関数＋お客様画面の計算＋管理画面の表示を同時に変える。本番の注文ロジックの変更なので、初日に入れるか後日にするかも決める。
3. 明日は割引を OFF: 管理画面「メニュー ＞ セットドリンク」のトグルで店舗が切れる。ノンアルの割引も消える。

### 2. 注文を止めるスイッチ（A3）
1. 今夜 UI を足す（表示設定 ＞ 使う機能に「注文の受付」トグル。SQL 1本＋小さな画面変更）。店側が自分で止め・戻せる。
2. 当日は天真か AI が SQL で切り替える（`UPDATE public.stores SET is_accepting_orders=false …`）。連絡→操作の遅れが出る。
3. 用意しない。プリンタ停止中も注文が入り続ける。
注意: 今のフラグはお客様の端末側でしか見ていない（サーバーの place_order は見ない）。止めても「注文を確定する」が止まるだけで、機構的な遮断ではない。

### 3. 注文・会計の取り消し手段（`cancelled` が無い）
今は SQL でしか戻せない。二重注文の削除は `order_item_options → order_items → print_jobs → orders` の順に DELETE、誤会計は `UPDATE public.orders SET status='pending' WHERE id='…'`。
1. 明日はこのまま（天真が SQL で対応）。
2. 後日、`cancelled` 状態と管理画面の「取り消す」を設計する（注文・会計ロジックの変更）。

### 4. 二次元コードが解決できなかったお客様の扱い（A1 / S3）
1. 卓なしで注文を通す（今のまま＋「前の卓を消す」修正）: 伝票は受渡番号だけ、レジは「—」の1枚に合流する。
2. 解決できなかったら「スタッフをお呼びください」と出して止める: お客様向けの新しい文言が要る。
3. 1 に加えてレジで卓なし注文を1件ずつ別の伝票にする: 会計ロジックの変更。

### 5. 価格をサーバー側で引き直すか（O3）
1. 今のまま（営業中に価格を変えない運用）。
2. place_order が menu_items.price を使うように変える（注文確定ロジックの変更。改ざんにも強くなる）。

### 6. 印刷済み伝票の刷り直し（P3）
1. 今のまま（紛失時は天真が SQL で戻す）。
2. 「最近印刷した伝票」にも「刷り直す」を出し、押すと「同じ伝票が2枚出ます」と確認を挟む。管理画面の新しい文言が要る。

### 7. 売り切れの即時反映（A5）
1. 今夜 `ALTER PUBLICATION supabase_realtime ADD TABLE public.menu_items;` を流す（1行。戻すのも1行）。
2. 流さず、ホールに「開きっぱなしの画面には次のページ移動まで出ない。注文は必ず弾かれる」と申し送る。

### 8. 退店ガードの線引き（C2）
1. 「JST の同じ日」の注文だけで判定する（明日以降、再来店で THANK YOU が出なくなる）。
2. 直さず運用（検証端末は開店前に二次元コードを2回読んでリセット。お客様には「もう一度読んでください」）。

### 9. テイクアウト（S5）
テイクアウト商品を公開する日は、厨房画面を ON に戻して明細を「調理済み」にしないと受渡画面に出ない。使う予定があるなら、そのときの運用を決める。
