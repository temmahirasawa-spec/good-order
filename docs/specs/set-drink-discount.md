# セットドリンク割引（食事と一緒の注文でドリンクを割り引く）

**状態: 実装中（2026-09-13）。洋輔さんの依頼を天真が中継。**

> 食事とドリンクをご注文でドリンク200円引きになるので、フードの数分だけドリンクの金額 -200円
> （2名で来られて、パンケーキひとつとドリンク2つだと、ドリンク1つ分だけ200円引き）
> 自動適用できれば助かります

---

## 1. 割引の決まり（このとおりに計算する）

| 項目 | 決まり |
|---|---|
| フード | カテゴリーの**区分が「フード」**の商品（`categories.category_type = 'food'`） |
| ドリンク | カテゴリーの**区分が「ドリンク」**の商品（`category_type = 'drink'`） |
| 割引が付く杯数 | **min（フードの合計点数, ドリンクの合計点数）** |
| 1杯あたりの割引額 | 設定値（既定 **200円**）。ただし**そのドリンクの単価を超えない** |
| どのドリンクから引くか | **単価の安い順**。100円のドリンクに200円引いて마이너스にならないようにするため |
| 税 | 割引は**税抜きの小計から引く**（この店の価格は税抜き。`小計 − 割引` に 10% を掛ける） |
| 対象の注文 | 既定は**店内のみ**。管理画面のトグルでテイクアウトにも広げられる |

### 例

- パンケーキ1 ＋ コーヒー2 → 割引は **1杯ぶん**（min(1, 2) = 1）＝ **200円引き**
- パンケーキ2 ＋ コーヒー2 → **2杯ぶん** ＝ 400円引き
- パンケーキ1 のみ、またはコーヒー2 のみ → **割引なし**
- パンケーキ1 ＋ 100円のドリンク1 → **100円引き**（単価を超えない）

### 決めたこと（AI 判断。いつでも覆せる）

1. **「安い順に、単価を超えない額を引く」**。マイナスの明細を作らないため
2. **既定は店内のみ**。依頼文が「2名で来られて」と店内の話なので。テイクアウトは設定で足す
3. **割引はオプション（トッピング）込みの単価に対して判定**する。ドリンクにトッピングが付いてもそのまま
4. **金額はサーバー側（`place_order`）で計算し直す**。お客様の画面が送ってきた合計は信じない
   （割引が絡むと、古い画面や改ざんで金額がずれる余地ができるため）

- 同じ行を**完了画面**と**注文履歴**にも出す

- 商品一覧・商品詳細には出さない。カートで初めて出る
  （どの組み合わせで付くかは「小計の下」でまとめて伝えるほうが分かりやすいため）

## 3. 店舗側

### 3-1. 管理画面「セットドリンク」（新規、メニューの下）

サイドバー「メニュー」の中に **「セットドリンク」** を追加。ここだけで設定が完結する。

| 置くもの | 中身 |
|---|---|
| トグル | セットドリンク割引を使う（既定 OFF） |
| 数値 | 1杯あたりの割引額（円）。既定 200 |
| トグル | テイクアウトの注文にも適用する（既定 OFF） |
| 説明 | 「フード1品につき、ドリンク1杯まで割引します」＋ 上の例 |
| 対象カテゴリー | いま「フード」「ドリンク」になっているカテゴリーを一覧で見せる（区分の変更は「カテゴリ管理」へのリンク） |

### 3-2. レジ

`orders.total_amount` は**割引後の金額**なので、会計の流れは変わらない。
内訳が分かるよう、割引のある注文には金額の下に「セットドリンク割引 −¥200」を出す。

### 3-3. 厨房伝票

**変更なし**（伝票に金額は刷らない決定のため）。

## 4. データの持ち方

| 場所 | 列 |
|---|---|
| `stores.set_drink_enabled` | boolean、既定 false |
| `stores.set_drink_discount` | integer、既定 200 |
| `stores.set_drink_takeout` | boolean、既定 false |
| `orders.discount_amount` | integer、既定 0。**その注文で実際に引いた額**（税抜き） |

- `place_order()` が明細とカテゴリーの区分から割引を計算し、`total_amount` を計算し直して保存する
- 保存 RPC `save_set_drink_setting()`（manager のみ）
- **RLS は緩めない**
