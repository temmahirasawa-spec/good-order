# レジの伝票編集（明細を消す／伝票ごと消す／足す）

_2026-09-21。洋輔さん経由の店舗の要望「会計の画面に来てから一切編集ができない」。天真の指示で設計・実装。_

## 1. 何を作るか

レジの会計画面で、会計する前に伝票を直せるようにする。

1. **明細を1行消す**（頼まれていないものが入っていた・お客様がキャンセルした）
2. **伝票（注文1回ぶん）ごと消す**（二重注文・間違った卓）
3. **商品を足す**（口頭で頼まれたものがアプリに入っていない）

## 2. 安全のための線引き

- **会計済み（paid）の注文には触れない。** レジ画面にはもともと会計前しか出ないが、DB 側でも弾く。
  売上（ダッシュボード・日報）は `status='paid'` しか見ていないので、**売上の数字は絶対に動かない**
- 触れる役割は **マネージャーとレジ**のみ。RLS では「レジは会計前の注文を触ってよい」を表現できないため、
  SECURITY DEFINER の関数の中で役割を見る（`supabase/register_edit.sql`）
- **楽観ロック**（注文の `updated_at` 一致）。他の端末が先に触っていたら何もせず、画面を取り直す
- 通常は見るだけ。「**伝票を直す**」を押している間だけ消す・足すができる。編集中は「会計済みにする」を出さない
- 消すときは必ず確認の窓。文言は会計の確認と同じ形（「この操作は取り消せません」）

## 3. 画面

### 通常（これまでどおり）
明細は「店内／テイクアウト」でまとめ、小計・割引・消費税・合計を出す。下に「会計済みにする」と「伝票を直す」。

### 編集中
- 明細を**伝票（注文1回ぶん）ごと**に並べ替える。どの行がどの伝票かが見えないと、伝票ごと消すのが危ないため
- 各伝票の見出しに「N回目・受渡番号・時刻」と「この伝票を削除」
- 各行の右に削除ボタン
- 下に「商品を追加」と「編集を終える」
- **編集中は金額を出さない。** 書き換えるたびにサーバーが計算し直すので、途中の数字を画面で足し引きすると必ず食い違う
  （2026-09-15 にレジと客側で金額が食い違った反省）

## 4. 金額の作り直し

レジ画面は 合計・割引・消費税を `orders` の列から読み、小計だけ明細から計算している。
明細をいじると両者が合わなくなるので、**書き換えた時点で `orders` を書き直す**。

セットドリンク割引は「同じ卓の会計前の注文ぜんぶ」で数える（`docs/specs/set-drink-discount.md`）ため、
1件だけ直すと後の注文の割引が古いまま残る。そこで **その卓の会計前の注文を古い順に全部計算し直す**
（`recalc_bill_totals`）。計算そのものは place_order と同じ関数（`calc_order_total` / `set_drink_discount_for`）を使う。

> ⚠ 税率は「今の設定」で計算し直す。注文したときの税率ではない。
> 営業中に税の設定を変えない運用（`docs/specs/tax-mode.md`）が前提。

## 5. 「足す」は新しい注文にする

自前で `order_items` に入れず、**既存の `place_order` をレジから呼ぶ**（同じ卓への追加注文）。理由:

- 伝票は `orders` の INSERT のトリガーで作られる。直接明細を足すと**厨房に伝票が出ない**
- 売り切れの確認・オプションの価格・セットドリンク割引・消費税・受渡番号が全部そのまま効く
- 既存の「追加(2)」とまったく同じ道なので、厨房・レジ・伝票の見え方が揃う

提供タイミングはレジからは選ばない（足すのはたいてい既に出ているもの）。

## 6. 明細が0件になるとき

最後の1行を消したら、**注文ごと消す**。明細0件の注文は厨房画面の「すべて調理済み」の判定
（`items.length > 0 && every(done)`）が永久に false になり、カードが消えなくなるため。

## 7. できないこと（今回は作らない）

- **数量だけ減らす**（1行まるごと消すか、消して足し直す）
- **会計済みの取り消し**（従来どおり天真が SQL で戻す）
- **お客様の画面の訂正。** 注文履歴と完了画面はお客様の端末に保存された控えを出しているので、
  レジで直しても**お客様のスマホには古い内容が残る**。金額の説明は口頭で
