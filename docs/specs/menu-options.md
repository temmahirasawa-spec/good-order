# メニューのオプション（トッピング）

**状態: 確定（2026-09-04、天真の決定）。** 決定の要点: 器は **A（商品詳細の中に一覧）**、無料は **「0円」** と表示、
**選び方（複数選択＝チェック／1つだけ＝ラジオ）を商品ごとに管理画面で設定**（グリーンサラダボウルは複数選択）。
その他は提案どおり。決定の記録は末尾「9. 決めてほしいこと」。

---

## 1. 何を作るか

商品ごとに「追加で選べるもの」（トッピング・具材・サイズ違い等）を管理画面から設定でき、
お客様は商品を選んだあとに **二段階目としてオプションを選んで** 注文できるようにする。

- 最初の対象は YORKYS BRUNCH の **グリーンサラダボウル**（880円）。12種のトッピング（100〜200円）。
- **店舗専用の機能にしない。** 管理画面のメニュー編集で、どの商品にも自由に設定できる。
- 既定ではオプションは **表示されない**（トグル OFF）。ON にすると設定画面が出る。
- 価格の入力欄はあるが **空欄＝無料** も可。

---

## 2. 用語と判定

| 用語 | 意味 | どこで決まるか |
|---|---|---|
| オプション | 商品に付けられる追加項目。名前と価格を持つ | `menu_item_options`（新設） |
| 対象商品 | オプションを選べる商品 | `menu_items.options_enabled` が ON、かつ有効なオプションが1つ以上 |
| 見出し | お客様画面でオプション一覧の上に出す文言。商品ごとに変えられる。既定「トッピング」 | `menu_items.options_heading`（新設） |
| 無料 | 価格が空欄（=0円）のオプション | 価格 0 |

選び方は商品ごとに管理画面で設定する（`menu_items.options_select_mode`）:
- **複数選択（チェックボックス）**: 任意（0個でも注文できる）・同じものは1つまで・上限なし。グリーンサラダボウルはこちら
- **1つだけ（ラジオボタン）**: 必ず1つ選ぶ。最初の項目が選ばれた状態で開く（AI の判断。「未選択で注文できない」より迷わない）
「グループ分け（野菜／たんぱく質）」「個数」は v1 では作らない（データの形は後から足せるようにしておく。8 章）。

## 3. お客様側の操作の流れ

```
一覧 ─ 商品を開く ─ 商品詳細 ─「カートに入れる」─┐
一覧 ─ カードの「カートに入れる」─────────────┤ 対象商品なら → オプションを選ぶ（3案の器）─ 決定 ─ カート
                                                    └ 対象外なら → そのままカート
カート ─ 行にトッピングが並ぶ ─ 注文を確定 ─ 完了画面（トッピングも表示）
```

### 3-1. 商品詳細
- 対象商品では、オプションを選ぶ UI が出る（どこに出るかが 6 章の3案）。
- 選ぶたびに下部バーの金額が変わる（880 → ＋アボカド ＋ゆで卵 で 1,100）。
- 「カートに入れる」で、選んだオプションつきでカートに入る。

### 3-2. 一覧のカードから直接「カートに入れる」
- 対象商品では **黙って「オプションなし」で入れない**。オプションを選ぶ UI を開く（案 B / C ならそのまま同じ画面）。

### 3-3. カート
- 行の商品名の下に選んだオプションを「＋アボカド ＋ゆで卵」のように列挙。行の単価はオプション込み。
- 同じ商品でもオプションの組み合わせが違えば **別の行**。
- 変更は v1 では「行を削除して入れ直す」（案 B / C なら行の「変更」からシートを開く拡張が自然。9-6）。
- 提供タイミング（`docs/specs/serving-timing.md`）と両方対象の商品は両方出る。順番は オプション → 提供タイミング。

### 3-4. 完了画面・注文履歴
- 商品名の下にオプションを列挙。再注文でもオプションを引き継ぐ（その時点で消えたオプションは落とす）。

## 4. 店舗側

### 4-1. 伝票（`lib/receipt.ts`）
```
1       サラダ グリーンサラダボウル
        ＋アボカド
        ＋ゆで卵
```
品名の下に1行ずつ「＋名前」。文字の大きさは品名と同じ倍高（厨房から読めるように）。提供タイミングがある場合はその下。

### 4-2. 厨房画面
品名の下に小さく「＋アボカド ＋ゆで卵」。提供タイミングのバッジはその横。

### 4-3. レジ・売上
- 行の単価はオプション込み（`order_items.unit_price` に込みで保存）。**既存の合計・消費税・売上集計はそのまま効く。**
- 内訳（どのオプションがいくらか）は `order_item_options` に残す。レジの明細に内訳を出すかは 9-7。

### 4-4. 管理画面「メニュー管理」の編集パネル
- 「テイクアウト」トグルの下に **「オプション」トグル**（既定 OFF）。
- ON にすると下に設定が開く（**薄いグレーの枠で束ねる**。天真の決定 2026-09-04。小見出しの文字は 12px 太字のまま小さくしない）:
  - 見出し（既定「トッピング」）
  - 一覧: 行ごとに 名前 ／ 価格（空欄＝無料）／ 表示する（ON/OFF）／ 並び替え（⠿）／ 削除
  - 「＋ オプションを追加」
- 保存は商品と一緒（パネルの「保存する」）。追加・変更・削除をまとめて反映。
- 注文済みのオプションを消しても、過去の注文には名前と価格のスナップショットが残るので影響しない。

## 6. お客様側の3案（器だけを変える。中身は同じ）

中身（共通）: 見出し「トッピング」、チェック式の一覧（名前・価格、無料は「無料」）、選ぶと金額が変わる、決定ボタンに合計金額。

| 案 | 器 | 一覧カードからの直接投入 | 強い店舗・状況 |
|---|---|---|---|
| **A 詳細の中に一覧** | 商品詳細の説明文の下にチェック一覧を置く。1画面で完結。下部バーの金額が変わる | 詳細を開いて選ばせる | 選択肢が少ない商品が多い店。常連が多く、画面を増やしたくない |
| **B 半モーダル** | 「カートに入れる」を押すと下からシートが出て、そこで選んで「カートに入れる ¥1,100」。詳細は今のまま | 同じシートを開く | **天真の書いた二段階の流れそのもの**。選択を意識させたい、選択肢が多い商品（サラダ12種） |
| **C 全画面の選択ページ** | 一覧から選ぶと、詳細を挟まずに「トッピングを選ぶ」の全画面へ（上に商品の要約、下に一覧、下部バーで決定） | 同じページへ | 選択が主役の商品（サラダ・丼のカスタム）。写真より構成を見せたい店 |

**決定（2026-09-04）: A。** 商品詳細の説明文の下（提供タイミングの上）にチェック一覧を置き、下部バーの金額が「カートに入れる ¥1,100」のように変わる。
一覧のカードから直接入れたときは商品詳細を開く（そこで選ぶ）。

## 7. データの形（DB スキーマの変更。天真の確認が要る）

新規ファイル `supabase/menu_item_options.sql`。本番の Supabase なので AI は流さない。

| 変更 | 中身 |
|---|---|
| `menu_items.options_enabled` | boolean、既定 false（管理画面のトグル） |
| `menu_items.options_heading` | text、既定 'トッピング' |
| `menu_items.options_select_mode` | text、既定 'multiple'。CHECK: 'multiple'（チェック）/ 'single'（ラジオ） |
| `menu_item_options`（新設） | id / menu_item_id / name / price（integer、既定 0 ＝無料）/ display_order / is_available / created_at。RLS は menu_items と同じ（読み取り全員、書き込み認証済み） |
| `order_item_options`（新設） | id / order_item_id / option_id（消えても残るよう NULL 可）/ name / price（注文時点のスナップショット）。RLS は order_items と同じ |
| `place_order()` | 明細の `options: [{option_id}]` を受け取り、**価格はサーバー側で DB から引き直して** `unit_price` に足す（お客様側の値を信用しない） |
| `claim_print_job()` | 明細に `options: [{name, price}]` を足す |
| 初期データ | グリーンサラダボウル（`17bc4c4d-…`）に ON と12件。画像のとおり: アボカド120 / キャロットラペ100 / さつまいもコンポート100 / かぼちゃマッシュ100 / ブロッコリー100 / ハーブ蒸し鶏180 / 無添加ロースハム200 / スモークサーモン180 / 生ハム180 / ゆで卵100 / カッテージチーズ120 / グリークヨーグルト120 |

流す順番は前回と同じ: **SQL → マージ**。

## 9. 決めてほしいこと（2026-09-04 に天真が決定した記録）

1. **お客様側の器**: **A 詳細の中に一覧**
2. **無料の見せ方**: **「0円」と書く**
3. **選び方**: **商品ごとに管理画面で「複数選択（チェック）／1つだけ（ラジオ）」を選ぶ。** グリーンサラダボウルは複数選択
4. **見出しの文言**: 既定「トッピング」、商品ごとに変えられる（提案どおり）
5. **カードからの直接投入**: 選択 UI（商品詳細）を開く
6. **カートでの変更**: 削除して入れ直し
7. **レジの明細**: 込みの単価だけ
8. **伝票の印字**: 「＋名前」を品名と同じ大きさで1行ずつ
9. **文言**: そのまま。ただし無料は「無料」ではなく「0円」
