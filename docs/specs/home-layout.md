# トップの構成・「すべてを見る」・サブカテゴリー

**状態: 確定（2026-09-08 に天真が決定）。** 決定の記録は末尾「7. 決めてほしいこと（決定の記録）」。Figma の記録は「8. Figma」。

## 1. 天真の整理（2026-09-08）

1. トップは「一部が見えていて、見出し右上の『すべてを見る』で縦スクロールの一覧ページへ」が自然。
   ドリンクや文字メニューを全件出すと冗長。フードも含めて全カテゴリーに「すべてを見る」を置く。
2. ドリンクは上に。並びは **キービジュアル → ベストセラー／おすすめ → ドリンク → フード**。
   上に置く分、上位5品程度＋「すべてを表示」で縦の長さを抑える。
3. ドリンク・アルコールは幅が広い（カフェ／ソフトドリンク、ジンベース／ビール／ワイン／シャンパン）ので **サブカテゴリー** が要る。

## 2. 今との違い

- 2026-09-07 の PR #60 で「トップにそのカテゴリーの全件（上限30）」にしたばかり。**この案はそれを上書きする**（全件 → 上位 N 件＋すべてを見る）。
- 一覧ページ `/order/[category]` は既にある（写真グリッド）。「すべてを見る」の遷移先はこれを使い、文字リスト（menu-text-rows）にも対応させる。
- カテゴリーは今は1階層（`categories`）。サブカテゴリーは新設。

## 3. トップの構成（案）

| 順 | 区画 | 中身 |
|---|---|---|
| 1 | キービジュアル | 動画（今のまま） |
| 2 | ベストセラー | 今のまま（Wide カード） |
| 3 | **ドリンク**（区分 = drink の親カテゴリー） | 上位 N 件の文字リスト＋「すべてを見る」 |
| 4〜 | フードの各カテゴリー | 上位 N 件の写真カード（横スワイプ）＋「すべてを見る」 |

- **N の既定は 5**（天真の目安）。管理画面「カテゴリ管理」で 3 / 5 / 8 / 全件 から選べるようにする（9-3）。
- 「すべてを見る」は見出しの右（Link Button）。**N 件で収まっているカテゴリーでも出す**（一覧ページに縦で見られる場所がある、と学習させるため）。9-2 で確認。
- 上位 N 件の並び: 管理画面の並び順（display_order）。人気順にするかは 9-4。
- タブナビの順もこの並びに合わせる（おすすめ → ドリンク → フード…）。

## 4. 一覧ページ（`/order/[category]`）

- 縦スクロール。写真ありは今のグリッド、写真なしは文字リスト（menu-text-rows の決定に従う）。
- サブカテゴリーがある親カテゴリーでは、**上にチップ（すべて／カフェ／ソフトドリンク／…）、本文はサブカテゴリーごとの見出しで区切る**。チップは絞り込み（or 見出しへジャンプ）。

## 5. サブカテゴリーの3案（トップのドリンク区画の器だけ変える）

| 案 | 器 | 強い店舗・状況 |
|---|---|---|
| **A チップで絞り込む** | 区画は1つ。見出しの下にチップ（すべて／カフェ／ソフトドリンク／アルコール）。押すとその区分の上位 N 件に入れ替わる | ドリンクが多く、トップを短く保ちたい店（YORKYS） |
| **B サブカテゴリーごとに区画** | カフェ／ソフトドリンク／アルコールが別々の区画（それぞれ N 件＋すべてを見る）。タブも増える | 区分ごとの主張が強い店（バー、居酒屋） |
| **C 一覧ページだけで区切る** | トップは上位 N 件の1区画のみ。区分は一覧ページの見出しとチップにだけ出る | 仕組みを最小にしたい。まず一覧ページで様子を見たい |

AI の推奨: **A**。トップの長さを増やさず、区分の存在を伝えられる。B は区画が増えてトップが長くなる（天真の懸念そのもの）。C は最小だがトップで区分が見えない。

## 6. データの形（案）

- `categories.parent_id uuid NULL`（自己参照）。親が NULL = 今のカテゴリー、親あり = サブカテゴリー。
  トップとタブには親だけを並べ、サブカテゴリーは親の中で display_order 順。
- `categories.top_limit integer NOT NULL DEFAULT 5`（トップに出す件数。0 = 全件）
- 商品は今までどおり `menu_items.category_id`。サブカテゴリーがある場合は**サブカテゴリー側に紐づける**（親に直接ぶら下がる商品も許す＝区分未設定として「その他」扱い）。
- 既存データは全部が親（parent_id NULL）なので、そのまま動く。

## 7. 決めてほしいこと（2026-09-08 に天真が決定した記録）

1. **サブカテゴリーの器**: **A チップで絞り込む**（トップのドリンク区画。チップを押すとその区分の上位 N 件に入れ替わる）
2. **「すべてを見る」**: N 件で収まっていても出す（提案どおり）
3. **N の既定と設定**: 既定5、カテゴリーごとに 3/5/8/全件（提案どおり）
4. **上位 N 件の並び**: 管理画面の並び順（提案どおり）
5. **タブの順**: おすすめ → ドリンク → フード… にトップと揃える（提案どおり）
6. **サブカテゴリーのデータ**: `parent_id` の2階層（提案どおり）
7. **一覧ページの上部の操作（天真の指定）**: トップの上部タブと**同じ挙動**にする。タブを押すとその区分の見出しへ**縦スクロールで移動**する（絞り込みではない）。
   見た目もトップのタブ（下線つき Tab Nav）と同じ。トップのドリンク区画の**チップ（絞り込み）とは役割が違う**ので、UI を切り分ける:
   - トップのドリンク区画 = **Filter Chip**（押すと中身が入れ替わる）
   - 一覧ページの上部 = **Tab Nav**（押すとその見出しへスクロール。トップのタブと同じ）
8. 写真なしの文字メニュー（`menu-text-rows.md`）は **A 行リスト**で進める（トップの絵がそれで、そのまま同意）
