# Step 3-I: 厨房画面の新デザイン実装（PC・SP両対応）

既存の厨房画面（`/admin/kitchen`、リアルタイム更新・ステータス管理などの機能は
既に実装済み）の**見た目を新デザインに差し替え**ます。データ取得・realtime購読・
ステータス遷移ロジックは一切変更せず、コンポーネントの見た目だけを今回のFigmaデザインに
合わせてください。

Figma参照: `Kitchen / 厨房`セクション（PC: `Template / Kitchen 1180x820`、
SP: `Kitchen — Mobile 390` + `Kitchen — Mobile Nav Open`）

---

## 1. 共通インフラ（PC・SP共有、レジ画面でも再利用します）

### Nav Sidebar v2（PC専用、220px幅・画面高さ一杯）
- 上部: 「GOOD ORDER」ワードマーク
- ナビ項目: ダッシュボード／厨房／レジ／メニュー管理（アコーディオン、開くと
  「カテゴリ管理」が中に入る想定）／テイクアウト管理。現在地のページはActive状態
  （背景ink・文字inverse、以前実装したToggleと同じ配色ルール）
- 下部: スタッフ名（「厨房スタッフ」等、ログイン中のロールに応じて表示）＋ログアウト

### Nav Drawer（SP専用、ハンバーガーで開くオーバーレイ）
- 内容はNav Sidebar v2と同じナビ項目一式。スクリム＋左からスライドする280px幅の
  ドロワー

### PC/SP共通のTop Barパターン
- 左: ページタイトル（「厨房」）＋ステータス数（例:「対応中 6卓」）
- 右（SPはタイトル行の右端、PCは同じ行）: リアルタイムで対応中の卓数を表示

## 2. スタッフ呼び出し表示（Staff Call Chip）

呼び出し中のテーブルがある場合、Top Barの下に横並び（PC）／横スクロール（SP）で
表示。既存の「スタッフ呼出」機能のUIをこのコンポーネントに差し替えてください。

- `State=Waiting`: 呼び出し発生直後（未対応）
- `State=Acknowledged`: スタッフが対応ボタンを押した後
- 経過時間（「2分」等）はリアルタイムで更新
- Action Buttonタップで「対応する」→Acknowledged状態に変化、既存のスタッフ呼出
  解決フローをそのまま呼び出してください

---

## 3. 注文カード（Order Card）

PCは2列グリッド、SPは1列で縦に並べます。

- **Header**: テーブル番号 + 経過時間（「5分経過」）
- **Items**: 注文アイテムごとに1行（品名 + `Status Badge`）、行間に区切り線
  - Status Badge: `未調理` → `調理中` → `調理完了` → `提供済み` → `受渡済み`
    の5状態。既存のステータス遷移ロジック（DBの`order_items.status`等）と
    そのままマッピングしてください
- **Footer**: 進捗テキスト（「調理中：1/2品」等、Items内の完了数/全体数から算出）+
  完了ボタン（「調理完了にする」等、既存のステータス一括更新アクションを呼び出す）

### 緊急度（Urgency）による見た目の変化
Order Cardには3つのバリアントがあります。既存の「経過時間に応じた警告表示」ロジックが
あれば、そのまま以下にマッピングしてください（無ければ、経過時間の閾値をこちらで
決めて実装して構いません。目安として15分未満=Normal、15〜25分=Warning、
25分以上=Urgentのような区切りを提案します）。

- `Urgency=Normal`: 通常
- `Urgency=Warning`: やや時間経過（背景・枠に軽い注意色）
- `Urgency=Urgent`: 長時間経過（背景・枠に強い警告色）

## 4. データ・確認したいこと

- 既存のSupabase realtimeの購読・ステータス更新のミューテーション処理は
  そのまま流用してください。今回のスコープは表示コンポーネントの差し替えのみです
- 経過時間によるUrgency判定の閾値（上記15分/25分は仮の提案）は、既存に近い基準が
  あれば教えてください。無ければこちらの提案で進めます
- モバイルでの「対応中の卓数」表示は、PCと同じ集計ロジックを流用して問題ないか
  確認をお願いします
