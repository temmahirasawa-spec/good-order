## 1. サイドバーの並び替え（先に対応・全管理画面に影響）

`Nav Sidebar v2`（`319:369`）と`Nav Drawer`（`319:442`）の項目順を変更しました。
Figma側は修正済みです。以下に合わせてください。

### 新しい順序

```

厨房
レジ
テイクアウト
─────────────  ← 区切り線
```

### 変更点

1. **毎日使う画面を最上部に**: `厨房` / `レジ` / `テイクアウト` の3つ。営業中に最も
   触られる順番です
2. **区切り線を1本入れる**: 上記3つと「メニュー」の間。日々のオペレーション用の画面と、
   設定・管理系の画面を視覚的に分けます
   - 実装: 上下パディング8・左右パディング12の中に1pxの`border/divider`
3. **`テイクアウト管理`の項目を削除**: `/admin/takeout`は`/admin/menu`に統合済みなので、
   既に消えているはずです（未対応なら削除してください）
4. **`テイクアウト受渡` → `テイクアウト` にリネーム**: `テイクアウト管理`が無くなり
   区別の必要がなくなったので、短くしました。遷移先は`/admin/pickup`のままです
5. **`ダッシュボード`を最下部へ移動**: ログアウトセクションのすぐ上に配置します。
   営業中に常時見る画面ではなく、締め後や振り返りで開くものなので、優先度に合わせて
   下げました
   - 実装: 間のスペーサーを`flex-grow`させて、ダッシュボードとログアウトを下端に寄せる形です
     （Figmaも同じ構造にしてあります）

## 2. SP版ダッシュボードの全体構成（上から順）

| # | セクション | 高さ |
|---|---|---|
| 1 | Top Bar | 68 |
| 2 | Tab Nav（アンカーリンク） | 50 |
| 3 | Period Selector | 66 |
| 4 | Page Content（カード9枚） | 可変 |

Page Contentは左右パディング16・上20・下32、カード間16px。カードは全て白背景・角丸16。

SPは全9枚のカードを縦1列に並べる構成で、**単なるPC版の縮小ではなく、モバイル向けに
情報設計を組み替えています**。以下の意図を踏まえて実装してください。

### Top Bar
- 左: ハンバーガー（Nav Drawerを開く）＋「ダッシュボード」
- 右: **CSV出力をアイコンのみの丸ボタン（40×40、`bg/tertiary`）に圧縮**
  モバイルではCSV出力の使用頻度が下がるため、テキストボタンから格下げしています

### Tab Nav（アンカーリンク）
お客様側TOPページと同じ`TabNav`コンポーネントを流用してください。カードが9枚あり縦に
長いため、目的のセクションへ飛べるようにするのが狙いです。

- タブ: `売上` / `推移` / `人気メニュー` / `ピーク帯` / `カテゴリ` / `稼働` / `客単価` / `比較`
- 各カードに対応する`id`を振り、タップでスムーズスクロール
- **スクロール位置に応じたアクティブ切り替え**（`IntersectionObserver`。TOPページと同じ実装を
  流用できるはずです。ヘッダー＋TabNav＋Period Selectorのぶんのオフセットに注意）
- Top Barの直下にsticky

### Period Selector
- **左端に「期間：」ラベル**（`type-jp-caption-bold`・`text/secondary`）
- その右に期間チップを横スクロール: `今日`（初期選択）/ `昨日` / `今週` / `先週` / `今月` /
  `先月` / `過去3ヶ月` / `カスタム`
- チップ: パディング左右14・上下8、角丸full。選択中は`accent/primary`背景、
  非選択は`bg/tertiary`背景。文字は両方`text/primary`
- 行の下パディング16

## 3. カード9枚（SP）

### ① Hero KPI Card
**売上合計だけを単独で大きく見せます。** PC版は6つのKPIが横並びですが、モバイルで
6つを均等に並べると全部が小さくなり優先順位が消えるため、最重要の1つだけ引き上げました。

- ラベル「売上合計」（`type-jp-body`・`text/secondary`）
- 数値: **`type-en-data-xl`（28px）**・`text/primary`
- 右隣に前期比のバッジ（`+12%`、緑系の淡い背景のピル、`type-jp-caption-bold`）
- パディング20

### ② Secondary KPI Grid
残り5つのKPIを**2列のグリッド**（折り返し）で表示。カード幅174px・間隔10px。
`会計組数` / `客単価` / `席回転率` / `店内比率` / `テイクアウト比率`

各カードは既存の`Stat Card`（ラベル＋数値＋前期比）。店内比率・テイクアウト比率は
前期比を持たないので非表示にしてください。

### ③ Sales Chart Card「時間帯別 売上推移」
PC版は棒グラフ＋折れ線の2軸ですが、**SPでは棒グラフのみ**にしています（狭い幅で2軸を
重ねると判読できないため）。11〜18時の8本、`accent/primary`、上部角丸4。

### ④ Popular Menu Card「人気メニュー」
**PC版のTOP5カードとTOP10カードを1枚に統合しています。** 内容が重複していたためです。

- タブ（`全体` / `フード` / `ドリンク`）: 選択中`accent/primary`、非選択`bg/tertiary`
- TOP5を「商品名＋食数」の行＋**横棒バー**で表示（1位を最大値として相対長さ）
  - バー: 背景`bg/tertiary`、前景`accent/primary`、高さ8・角丸4
- 末尾に「もっと見る（TOP10） ›」（`type-jp-caption-bold`・`text/secondary`）
  タップで残り5件を展開、という段階開示です

### ⑤ Peak Time Heatmap Card「曜日 × 時間帯 ピークタイム」
**PC版の15列（11〜25時）を、朝/昼/夜/深夜の4区分に集約しています。** 小画面で15列は
潰れて判読不能になるためです。各セルは元データの該当時間帯の平均値で塗ってください。

- 行: 月〜日の7行、左に曜日ラベル（20px幅）
- 列: 朝 / 昼 / 夜 / 深夜（各セルは幅fill・高さ28・角丸6）
- ヘッダー行に区分名（`type-jp-micro-label`・`text/secondary`）

### ⑥ Category Breakdown Card「カテゴリ別売上」
**PC版の円グラフを、積み上げ横バー＋凡例リストに置き換えています。** 小さい円グラフは
判読性もタップ性も低いためです。

- 上部: 全カテゴリを比率で並べた積み上げバー（高さ16・角丸8）
- 下: 凡例リスト（色ドット8px＋カテゴリ名＋パーセント右寄せ）
- 色はPC版と同一のパレットを使ってください

### ⑦ Table Utilization Card「テーブル稼働」
横スクロールする縦棒グラフ（T1〜T12）。稼働が低い卓は赤系（`#DC2626`相当）で強調し、
ヘッダー右に「● 稼働低め」の凡例を置いています。

### ⑧ Spend Histogram Card「客単価分布」
8区分の縦棒グラフ。色はPC版と同じ青系です。

### ⑨ Dine-in vs Takeout Card「店内 vs テイクアウト」
- 凡例（店内=青 / テイクアウト=茶）
- 比較行3つ: `売上` / `件数` / `客単価` を「店内 vs テイクアウト」の形式で
- 下部に日別推移の積み上げ棒グラフ（月〜日）

## 4. PC版について

PC版のFigma（`289:1405`）は既存実装とほぼ同じ構成のはずです。**SPを実装する過程で
共通化できる部分は共通化しつつ、PC版は現状の見た目を大きく変える必要はありません。**

ただしSPで①人気メニューTOP5/TOP10を統合、②ヒーローKPIの導入、という整理をしたので、
**PC版でもTOP5カードとTOP10カードの重複は解消したいです。** どちらか一方に寄せる形で
問題ないか、実装を見て判断・報告してください（Figma側は僕が追随します）。

## 5. `tabular-nums`の追加（先に対応してください）

`typography.css`の`EN/Data`系クラス全て（`type-en-data-2xs` 〜 `type-en-data-xl`）に
**`font-variant-numeric: tabular-nums`を追加**してください。`EN/Price`系には既に入って
いるので、それに揃える形です。

理由: このダッシュボードは人気メニューの「142食」、テーブル稼働、KPI数値など、
**数字が縦に並ぶ箇所が多く**、桁が揃わないと見栄えが崩れます。呼び出し側で都度
`tabular-nums`を付ける運用は付け忘れが必ず出るため、クラス側に入れてしまうのが確実です。

Figmaのテキストスタイルはこの手のOpenType機能を安定して保持できないので、
**コード側を正とします**。
