# Step 3-O: テーブル・二次元コード管理画面の実装（新規機能・既存画面への波及あり）

管理画面の**新規機能**です。各テーブルの注文用URLを二次元コードとして一覧表示し、
ダウンロード・卓上カードのA4印刷ができる画面を作ります。

**ただしこれは単独の新規画面では終わりません。** テーブルの識別方法そのものが変わるため、
厨房・レジ・ダッシュボード・お客様側の入口にも波及します（5章参照）。
先に全体像を把握してから着手してください。

Figma参照: `QR Management / 二次元コード管理`セクション（`529:7575`、MobileOrderページ `32:2` 内）
- PC: `Template / 二次元コード管理 1180x820`（`529:2959`）
- SP: `二次元コード管理 — Mobile 390`（`529:6939`）
- 印刷: `Print Sheet A4 (名刺サイズ10面)`（`529:5209`）／ `Print Card (91x55mm)`（`529:5037`）
- 席設定: `Modal / 席設定 — PC`（`541:793`）／ `Half Modal / 席設定 — SP`（`541:926`）
- コード選択: `Popover / コード選択 — PC`（`543:793`）／ `Half Modal / コード選択 — SP`（`543:848`）

---

## 0. 用語について（重要）

**「QRコード」は株式会社デンソーウェーブの登録商標**です。今後の製品化を見据えて、
**UI上の表記はすべて「二次元コード」**に統一してください。変数名・関数名などコード内部の
識別子は`qr`のままで構いませんが、**画面に出る文字列に「QR」を含めない**でください。
Figma側も全て「二次元コード」に統一済みです。

## 1. サイドバーへの追加

`テーブル・二次元コード`という項目を、**「メニュー」アコーディオンの直下**に追加してください
（Figma側は追加済み）。アイコンは新規の二次元コードアイコン（`Name=QR`）です。

```
厨房 / レジ / テイクアウト
──────────
メニュー（アコーディオン）
テーブル・二次元コード
　　（余白）
ダッシュボード
```

## 2. データモデル

### `table_categories`（新規）
| 列 | 説明 |
|---|---|
| `id` | PK |
| `code` | **英大文字1文字**（A〜Z）。カテゴリー間で一意 |
| `name` | 表示名（「カウンター席」「テーブル席」など） |
| `display_order` | 並び順 |

### `tables`（新規）
| 列 | 説明 |
|---|---|
| `id` | PK |
| `category_id` | `table_categories`への参照 |
| `number` | カテゴリー内の連番 |
| `short_code` | **URLに埋め込む不変の短いコード**（6文字程度のランダム英数字、全体で一意） |
| `display_order` | 並び順 |
| `legacy_number` | 移行前の数値テーブル番号（既存URL互換用、nullable） |

卓の表示ラベルは `category.code + number` で「A1」「B3」のように組み立てます。

### `orders`（既存テーブルの拡張）
- `table_id` … `tables`への参照（`ON DELETE SET NULL`）
- `table_label` … **注文時点のラベルのスナップショット**（"A1" などのテキスト）

**なぜ両方持つのか**: `table_id`だけだと、卓を削除したりカテゴリーのコードを変えたときに
過去の注文の表示が変わってしまい、「先週の伝票を見たら卓名が違う」という事故が起きます。
逆にラベルだけだと集計時に卓単位で正しくグルーピングできません。
**画面表示には`table_label`、集計・絞り込みには`table_id`**を使ってください。

## 3. URLの設計（重要な判断あり）

### 二次元コードのURLには`short_code`を使います

```
https://<host>/?t=k3f9x2
```

**ラベル（`?table=A1`）を埋めないでください。** ラベルを埋めると、あとで
「カテゴリーAをCに整理しよう」と変更した瞬間に、そのカテゴリーの**印刷済みカードが全部
無効になります**。しかも画面上はエラーにならず、お客様が読み取って初めて気づくため
発覚が遅れます。不変の`short_code`を使えば、コードも名称も何度でも安全に変更できます。

管理画面のカードには実際のURLを併記してあるので、スタッフはそこで確認できます。

### 既存URLとの後方互換（必須）

既存の`?table=5`形式のURLは、**すでに印刷されて店舗で使われている可能性があります**。
移行後もこの形式を受け付け、`legacy_number`が一致する卓に解決してください。
新しく発行する二次元コードは`?t=`形式にし、既存カードが差し替わるまでの間は
両方が動く状態を保ちます。

### 既存データの移行

- デフォルトのカテゴリーを1つ作成（コードは`A`、名称は「テーブル」あたり）
- 既存の全テーブル番号を`tables`行として作成し、`legacy_number`に元の番号、
  `number`にも同じ値、`short_code`は新規発行
- 既存の`orders`について、`table_id`と`table_label`をバックフィル

**既存の注文データが孤立しないことを最優先**にしてください。
移行SQLを流す前に、影響件数をSELECTで確認してから実行をお願いします。

## 4. 一覧画面

### Top Bar
- PC: 「二次元コード管理」＋右に「選択した{N}件を印刷」（ink塗りボタン）
- SP: ハンバーガー＋タイトル＋右に「＋」丸ボタン（席設定モーダルを開く）

### Sub Bar（PCのみ）
- 左: 選択状況のテキスト（例:「13件すべて選択中 ・ 名刺サイズ10面/A4 で印刷されます」）
- 右: 「**席カテゴリの設定・テーブルの追加**」ボタン（`bg/tertiary`）

### 一覧本体
**カテゴリーごとにグループ化**して表示します。

- グループ見出し: 「A ・ カウンター席」＋卓数（`JP/Heading/S` + `JP/Caption`）
- **テイクアウトのグループを最上部**に（1件のみ、パラメータなしのURL）
- カードはPCが4列グリッド、SPが1列
- 最後のグループの末尾に「＋ 卓を追加」の点線カード

### 二次元コードカード（`QR Card`）
```
☑ A1                    ⋯
   ┌──────────┐
   │  二次元   │
   │  コード   │
   └──────────┘
  good-order.app/?t=k3f9x2
  [コピー]  [DL]
```
- **チェックボックス**: 印刷対象の選択。`Checkbox`コンポーネントに
  `State=Active` / `State=Inactive` / `State=None` の3状態があります
- **⋯メニュー**: 「リンクを開く」（別タブで実際の注文画面を確認）／「削除」
- **コピー**: URLをクリップボードへ
- **DL**: 二次元コード画像のダウンロード。**PNGとSVGの両方**を選べるように
  （SVGは拡大しても劣化しないので、印刷業者に出す場合やメニュー表への埋め込みに必要）
- **テイクアウトのカードのみ**`accent/primary`の2px枠で区別

## 5. 既存画面への波及（見落とし注意）

テーブルの識別方法が変わるため、**卓名を表示している画面すべて**の対応が必要です。
今回のスコープに含めてください。

| 画面 | 現状 | 対応 |
|---|---|---|
| **お客様側の入口** | `?table=5`を数値として解析 | `?t=<short_code>`を受け付ける。`?table=N`も互換で維持。**どちらも無い場合はテイクアウト**という既存判定は変更しない |
| **厨房** | Order Cardのヘッダーに「テーブル 5」 | `table_label`（"A1"）を表示 |
| **レジ** | Table Chipに「TABLE 2」、会計カード | 同上。Chipのラベルも`table_label`へ |
| **ダッシュボード** | テーブル稼働カードが T1〜T12 | 実際の卓ラベル（A1〜C2）で表示。卓数も固定12ではなく実データの件数に |
| **お客様側の履歴・注文確認** | 卓番号を表示している箇所があれば | `table_label`へ |

**注意**: 厨房・レジは営業中に常時開いている画面です。移行の前後で表示が壊れないよう、
`table_label`が未設定の古いデータに対するフォールバック（元の数値を出す等）を
入れておいてください。

## 6. 席カテゴリーと卓の設定（PC=中央モーダル / SP=ハーフモーダル）

カテゴリーの管理と卓の追加を**1つの画面に統合**しています。別々の画面にはしないでください。

```
席カテゴリーと卓の設定                    [×]

⠿ [A ▾] [カウンター席        ] 🗑
     A1× A2× A3× A4× A5× A6×  ＋卓を追加
────────────────────────────────
⠿ [B ▾] [テーブル席          ] 🗑
     B1× B2× B3× B4×  ＋卓を追加
────────────────────────────────
＋ カテゴリーを追加

           [キャンセル]  [保存する]
```

- 卓を**チップで並べる**のは、「A3だけ撤去して A1・A2・A4… にする」といった
  歯抜けを表現できるようにするためです。単なる卓数の数値入力にすると、
  席レイアウト変更のたびに番号を振り直すことになります
- ⠿ でカテゴリーの並び替え
- 🗑 でカテゴリー削除。**そのカテゴリーに卓がある場合は件数を出して警告**してください
- **卓を削除しても、その卓での過去の注文は残ります**（`ON DELETE SET NULL` ＋
  `table_label`スナップショットのため）。削除確認の文言でその点に触れると親切です

### コード選択UI（A〜Z）
コード欄は**自由入力にしないでください**。自由入力だと「小文字が入る」「2文字打てる」
「他カテゴリーと重複する」の3つが起こり、後からバリデーションで弾くことになります。
選択式にすれば入力の時点で全部防げます。

- **PC**: コード欄直下に開く**ポップオーバー**。7列×4行でA〜Zが一画面に収まる（セル36px）
- **SP**: **ハーフモーダル**。6列でセル51px（タップ領域の推奨最小44pxを上回るサイズ）
- **他のカテゴリーで使用中のコードは`State=Disabled`**（グレー＋不透明度45%）で
  選択不可に。押してからエラーを出すより、最初から選べない方が親切です

## 7. 印刷（A4・名刺サイズ10面）

「選択した{N}件を印刷」で、卓上カードをA4に面付けした印刷用ビューを開きます。

### カードの中身（`Print Card`、91×55mm）
```
┌──────────────────────────┐
│ YORKYS BRUNCH   ┌───────┐│
│                 │ 二次元 ││
│ スマホでご注文   │ コード ││
│ いただけます     └───────┘│
│ [ テーブル A1 ]           │
└──────────────────────────┘
```
- 二次元コードだけ印刷しても卓上では機能しないため、ロゴ・案内文・卓名を入れています
- 二次元コードは**実寸で約31mm**（カード幅344pxに対し120px）。読み取り距離の目安は
  「コード幅の10倍」なので、30cm程度離れても読めます

### 面付け
- A4（210×297mm）に**2列×5行＝10面**
- 余白は左右53px・上下42px相当（96dpi換算）
- **カードの境界に沿って薄いグレーの切り取り線**
- `@media print`のCSSで組むのが素直です。`@page { size: A4; margin: 0; }`と
  mm単位での指定を推奨します
- 11件以上選択された場合は**複数ページに分割**してください

## 8. 確認したいこと

- 既存テーブル番号の移行方針と、影響件数（3章）
- 二次元コード生成ライブラリの選定（**SVG出力対応が必須**）
- 印刷ビューを別ページにするか、同一ページ内の`@media print`で切り替えるか
- 5章の波及対応で、想定外に影響範囲が広がった箇所があれば報告してください
