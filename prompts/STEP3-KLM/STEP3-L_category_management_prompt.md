# Step 3-L: カテゴリ管理画面の新デザイン実装（PC・SP両対応）

Menu Managementと同じく、こちらも**既存機能の見た目だけを新デザインに差し替え**ます。
`categories`テーブルへのCRUD・スラッグ自動生成・Realtime更新などのロジックは
既に実装済みなので変更せず、コンポーネントの見た目だけ今回のFigmaデザインに
合わせてください。Nav Sidebar v2／Nav Drawer／AdminPageShellはStep3-Iのものを
再利用してください。

Figma参照: `Categories Management / カテゴリ管理`セクション
（PC: `Template / Categories Management 1180x820`、
SP: `Category Management — Mobile 390` + `Category Editing — Mobile 390`）

## 1. 画面構成

### 一覧画面
- Top Bar: 「カテゴリ管理」＋新規追加ボタン（PC: テキストボタン、SP: 丸アイコンボタン）
- ヒント文言:「⠿ をドラッグして並び替えると、メニュー画面での表示順が変わります。」
- カテゴリリスト（新規`Category Row`）: ドラッグハンドル＋サムネイル画像＋
  タグ色ドット＋カテゴリ名/スラッグ＋（PC: 表示順バッジ／SP: 編集ボタン）

### 編集パネル（PCは右スライド420px幅パネル、SPは`Category Editing — Mobile 390`
のフルスクリーン。**SPはプレビュー無し**、これは元々PC側にもプレビューが無い
仕様なので変更なしです）
1. カテゴリ名（text）
2. スラッグ（text。新規作成時は名前から自動生成、編集時は自由に変更可という
   既存の挙動をそのまま維持してください）
3. キャッチコピー（textarea）
4. カテゴリ画像（1枚のみ。Menu管理と違い圧縮モーダルは無い既存仕様のままでOKです）
5. タグの色（`Color Swatch Picker`、10色固定スウォッチ）
6. 表示順（数値）
7. フッター: キャンセル／保存する

## 2. 見た目の差し替えと同時に直してほしい不備（コード調査済み）

**カテゴリ削除時の安全策を追加してください。** 現状、削除確認ダイアログは
「このカテゴリーに属するメニューアイテムも影響を受ける場合があります」という
控えめな文言ですが、実際のDBは`menu_items.category_id`が`ON DELETE CASCADE`の
ため、削除すると該当カテゴリの商品が全件削除されます。にもかかわらず件数警告が
無いため、誤操作で商品が丸ごと消えるリスクがあります。

対応方針: **削除自体はこれまで通り可能なままで構いませんが、確認ダイアログに
実際の件数を表示してください**（例:「このカテゴリには{N}件の商品があります。
削除すると商品も全て削除されます。本当に削除しますか？」）。削除をブロックする
必要はありません（天真さんとの相談の結果、警告表示のみで進める判断になりました）。
