# お客様向け画面のUI改善（ヘッダー統一・カテゴリカルーセル・詳細ページ再設計）

Figma側の修正はすべて完了しています。以下に合わせて実装してください。
参照: MobileOrderページ（`32:2`）内 `注文` セクション（`60:772`）

---

## 1. 円形ボタンのサイズ統一（全画面に影響）

バラバラだった円形ボタンを **48px** に統一しました。押しやすさを優先し、
iOSの最小推奨44ptを上回るサイズにしています。

| コンポーネント | 変更前 | 変更後 |
|---|---|---|
| `Header Icon Button`（☰ / ×） | 44 | **48** |
| `Back Button` | 52 | **48** |
| `Modal Close Button` | 36 | **48** |

`Modal Close Button` は管理画面のモーダルでも使われています。そちらも48に揃えて
問題ありません（同じ理由でタップしやすくなります）。

## 2. ヘッダーのレイアウト変更

**ルール**: ヘッダーのボタンは**常に右上**に1つだけ置きます（☰でも×でも同じ位置）。
左上にボタンは置きません。

| 画面 | ヘッダー |
|---|---|
| TOP | `Header / Open`（☰右上 ＋ ロゴ中央）を最上部に |
| Menu / カテゴリ一覧 | `Header / Close`（×右上 ＋ ロゴ中央） |
| ご注文を承りました | `Header / Open`（☰右上） |
| 商品詳細 | **×のみ右上**（KV画像に浮かせる）。**メニューボタンは廃止** |
| カート | 左に`Back Button`、右に☰（変更なし、サイズのみ48に） |

- 右端の余白16px（ボタン x=326）、ヘッダー高さ68pxに対し y=10 で垂直中央
- 商品詳細からメニューボタンを外したため、☰と×が同居する画面は無くなりました。
  Figmaで一時的に作っていた `Header / Menu + Close` コンポーネントは**削除済み**です

## 3. TOPページ

### 3-0. ヘッダーの追加と「カートを見る」バーの削除

- これまで左上に**浮いていたハンバーガーボタンを廃止**し、代わりに
  **`Header / Open`（☰右上 ＋ ロゴ中央、高さ68px）を画面最上部**に配置します。
  他の画面と同じヘッダー体裁に揃える形です
- Tab Nav はそのヘッダーの直下に来ます（sticky位置のオフセットが68px分ずれるので、
  scrollspyのオフセット計算も合わせて更新してください）
- **画面最下部の「カートを見る」バー（`Bottom View Cart Bar`）は削除**してください。
  3-3のフローティングカートボタンに一本化します（遷移先が同じで冗長だったためです）

### 3-1. カテゴリごとのカルーセル化（「もっと見る」を廃止）

各カテゴリの「2×2グリッド4件 ＋ もっと見るボタン」を廃止し、
**そのカテゴリの全メニューを横スワイプで見られるカルーセル**に変更します。

- `SeeMoreButton` は **TOPページから削除**してください
  （カテゴリ一覧ページ `/order/[category]` 自体は残します。Menuページからは引き続き遷移できます）
- 表示件数の制限を撤廃し、**そのサブカテゴリの全商品**を`display_order`順で並べます
  （`computeTopItemsBySubcategory(items, subcategory, 4)` の4件制限が不要になります）

**カードは新しいサイズ（`Menu Card M`、幅200px）を使ってください。**
ベストセラーの`Menu Card Wide`（300px）とも、グリッド用の`Menu Card`（171px）とも別物です。

レイアウト:
- 左パディング16、カード間12
- 1枚目 x=16、2枚目 x=228 → 画面幅390に対し**2枚目の右側が38pxはみ出す**
- これがスライド可能であることの視覚的な手がかりになります。この「見切れ」は
  意図的なものなので、`overflow-x`のスナップ設定などで潰さないでください

### 3-2. ドットページネーション

カルーセルの下に、**商品数ぶんのドット**を中央寄せで配置します（`Carousel Dots`）。

- 非アクティブ: 6×6・角丸3・`border/base`
- アクティブ: **18×6の横長**・角丸3・`surface/ink`
- **スクロール位置に連動**して動的に切り替えてください
  （`IntersectionObserver`か、スクロール量から算出する方式のどちらでも構いません）
- 商品数が多い場合（10件以上）はドットが横に伸びすぎるので、
  **最大表示数を決めて省略する**などの対応を入れてもらって構いません。方針は任せます

### 3-3. フローティングカートボタン

- 右下の**アラート（通知）アイコンを削除**してください
- 代わりに `Cart Icon Button`（`592:7864`）を**同じ右下の位置**に配置します
  - 48px円形・白背景・border・軽いshadow
  - **右上に数量バッジ**が重なります（下記スペック）
- タップで **カート画面へ遷移**
- 3-0で「カートを見る」バーを削除したので、**カートへの導線はこのボタンに一本化**されます。
  カートが空でも表示したままで構いません（バッジは0または非表示）

#### バッジのスペック（サイズを2段階上げました）
| 項目 | 値 |
|---|---|
| サイズ | **24×24**（従来16×16）。1桁のときは正円 |
| 文字 | **`type-en-data-s`（13px）**。従来より2段階大きく |
| 背景 | `accent/primary` |
| フチ | 白・**2.5px**（ボタンの白背景から浮かせるため） |
| 位置 | ボタンの右上に重なる（x=+7、y=-7のオフセット） |

2桁（例:「12」）になると幅だけ25pxに伸びます。3桁以上は「99+」等に丸めるかどうか、
実装側で判断してください。

**注意**: 削除するアラートアイコンがスタッフ呼び出し（`FloatingStaffCall`）である場合、
スタッフ呼び出し自体はMenuページの「スタッフを呼ぶ」から引き続き使えるので機能は失われません。
念のため確認をお願いします。

## 4. 商品詳細ページ（フルモーダル）

### 4-1. スクロール位置のバグ修正（重要）

モバイルで、TOPをスクロールした状態から商品をタップしてフルモーダルを開くと、
**TOPのスクロール位置が引き継がれて詳細ページが途中から表示される**バグがあります。

モーダルが開く際は**必ずコンテンツ最上部から表示**されるようにしてください。
Step3-Dでスライドアップのトランジションを`framer-motion`からCSSアニメーションに
置き換えた経緯があるので、その周辺が関係している可能性があります。
`scrollTo(0,0)`をトランジション完了後ではなく**開始前**に実行する必要があるかもしれません。

### 4-2. ヘッダー

- 左下にあった×を**右上へ移動**
- **メニューボタン（☰）は廃止**しました。フルモーダルからは×で閉じて元の画面に戻る
  導線があれば十分で、モーダル内にメニューを置くと階層が分かりにくくなるためです

### 4-3. 下部バーの再設計（`Bottom Detail Bar`）

カートに入れたことが伝わりにくい問題を解消するため、再設計しました。

```
┌──────────────────────────────────────┐
│  [🛒³]   [ − 1 + ]   [ カートに入れる ] │
└──────────────────────────────────────┘
```

- **背景を白に**（従来は透明）。上辺に`border/divider`の1px罫線
- **高さ76px**（左右パディング16・上12・下16）、要素間12px
- 構成（Figmaの実測値）:

| 要素 | 位置 | サイズ |
|---|---|---|
| `Cart Icon Button`（バッジ付き） | x=16 | 48×48 |
| `Frame 2`（下記2つを内包） | x=76 | 298×48、右寄せ・要素間8 |
| └ `Quantity Stepper` | Frame内 x=12 | 124×36 |
| └ 「カートに入れる」ボタン | Frame内 x=144 | **154×48** |

- ステッパーとボタンを`Frame 2`でまとめ、右寄せにしてあります。
  カートアイコンだけが左に離れる構成です
- 「カートに入れる」ボタンから**カートアイコンを削除**しました。左隣に
  カートアイコンがあるため重複するためです（ラベルのみ、99px）

### 4-4. バッジの動作（この画面の肝）

- 「カートに入れる」を押すたびに、**左のカートアイコンのバッジ数字が増える**
- 増分は数量ステッパーで選択した数（1個ずつとは限りません）
- **数字が変わったことが分かる短いアニメーション**（スケールのポップなど）を
  入れてください。ここが「カートに入った」ことを伝える主要なフィードバックになります
- バッジの数字はカート全体の合計数量です（この商品だけの数ではありません）

## 4-5. カルーセルカード（`Menu Card M`）の操作UI

カルーセル用のカード（幅200px）にも、商品詳細のBottom Detail Barと同じ
「数量ステッパー ＋ カートに入れるボタン」の並びを入れます。
**カートのボックスアイコンは入れません**（カードごとに置くと画面内で何度も繰り返され、
TOPのフローティングカートと役割が重複するためです）。

従来の幅いっぱいのステッパー（124×36）はこの幅に2要素を並べられないため、
**専用の小型コンポーネントを新規作成**しました。

| コンポーネント | サイズ | 備考 |
|---|---|---|
| `Quantity Stepper S`（`601:8129`） | **84×32** | ±ボタンは32px円形、数字は`type-en-data-m` |
| `Add to Cart Button S`（`601:8136`） | **108×32** | ラベルは`type-jp-caption-bold`（12px） |

- カード内は `Action Row`（横並び・要素間8）にこの2つを入れ、
  ボタン側を`flex-grow`させています（84 + 8 + 108 = 200）
- グリッド用の `Menu Card`（171px）は**従来のまま**です。今回変更したのは
  カルーセル用の `Menu Card M` だけです

## 4-6. ボタンコンポーネントの統一（表示バグ修正）

カートの「注文を確定する」ボタンが**高さ22pxに潰れて表示されるバグ**がありました。
内訳行の見切れを直した際に、同じ親の子要素をまとめて「内容に合わせる」設定にしてしまい、
ボタンまでラベルの高さになっていたのが原因です。

- カートの「注文を確定する」を**共有コンポーネント`Add to Cart Button`のインスタンス**に
  差し替えました（342×52・角丸999・`accent/primary`、アイコンは非表示）
- 同じく独自フレームで作られていた**ご注文確認画面の「追加で注文する」**も、
  同じコンポーネントに統一しました（56→52px）

実装側でも、この2つのCTAは商品詳細やカートバーで使っているものと**同じボタン
コンポーネントを使い回して**ください。個別にスタイルを書くと、同種のズレが再発します。
