# 【1】ベストセラー設定（新規機能）

トップページ最上部の「Best Seller」枠に何を出すかを、店舗側で設定できるようにします。
現在は`computeTopItems()`が注文数から自動算出していますが、**手動で選んだ商品を
指定順で出せる**ようにするのが目的です。

## 1-1. 導線

二次元コード管理の「席カテゴリの設定・テーブルの追加」と同じ見せ方で、
メニュー管理のTop Barに **「ベストセラーの設定」ボタン**（👑アイコン＋ラベル、`bg/tertiary`）を
置きます。SPは幅がないので**👑アイコンのみの丸ボタン（44px）**にしてあります。

- PC: `Modal / ベストセラー設定 — PC`（`620:863`、幅560の中央モーダル）
- SP: `Half Modal / ベストセラー設定 — SP`（`620:964`、ハーフモーダル）

## 1-2. モーダルの構成

```
ベストセラーの設定                              [×]
──────────────────────────────────────────────
┌────────────────────────────────────────────┐
│ トップページに表示する              [ON ●] │  ← bg/warm の帯
└────────────────────────────────────────────┘
ベストセラーは、トップページの最上部に横スライドで
表示されるおすすめ枠です。ここで選んだ商品が、
選んだ順番のまま表示されます（最大20件）。

登録済みの商品                            3 / 20
⠿  ①  [img]  パンケーキ プレーン              🗑
⠿  ②  [img]  エッグベネディクト クラシック     🗑
⠿  ③  [img]  自家製レモネード                 🗑

┌ 商品を追加 ────────────────────────────────┐
│ カテゴリ        商品名                       │
│ [パンケーキ ▾] [チョコ&バナナ ▾]    [選ぶ]  │
└────────────────────────────────────────────┘

                        [キャンセル] [保存する]
```

### 表示トグル
- **これがOFFのときは、トップページからBest Sellerセクションごと消えます**
  （セクション見出しも含めて非表示。空の枠を残さないでください）
- 背景に`bg/warm`の帯を敷いて、設定項目の中でも一段上の意味を持つことを示しています

### 補足説明テキスト
上記の文言（`type-jp-caption`・`text/secondary`）をそのまま入れてください。
「どこに」「どう出るか」が分かることが目的です。

### 登録済みリスト
- `Best Seller Row`（PC・`619:841`）／ `Best Seller Row (Mobile)`（SP・`619:862`）
- 構成: 並び替え操作 → 順位バッジ → サムネイル → 商品名＋カテゴリ名 → 削除
- **並び替え可能**。PCは⠿ドラッグ、SPは▲▼ボタン（【2】と同じルール）
- 右上に **`{件数} / 20`** を表示

### 追加フォーム
- 「カテゴリ」→「商品名」の順に選び、**「選ぶ」でリスト末尾に1件追加**
- 商品名の選択肢は、選んだカテゴリで絞り込んでください
- **すでに登録済みの商品は選択肢から除外**してください（重複登録を防ぐため）
- **20件に達したらフォームごと非表示**にし、「上限に達しました」等の一文に差し替えてください。
  押せるのにエラーになるより、押せない方が親切です
- 0件でも保存できます（その場合は表示トグルをOFFにする運用を想定）

## 1-3. データ

新規テーブルを想定しています（既存に近いものがあれば流用してください）。

| 列 | 説明 |
|---|---|
| `id` | PK |
| `menu_item_id` | `menu_items`への参照 |
| `display_order` | 並び順 |

表示ON/OFFは店舗設定のフラグ（`settings`テーブル等）に持たせてください。

**トップページ側の分岐**:
- 表示OFF → Best Sellerセクションを描画しない
- 表示ON かつ 登録0件 → **既存の`computeTopItems()`による自動算出にフォールバック**
  （設定はしたが中身が空、という状態で枠が消えると分かりにくいためです）
- 表示ON かつ 登録あり → 登録された商品を`display_order`順で表示

この分岐が過剰であれば、実装しやすい形に寄せてもらって構いません。方針だけ報告してください。

# 【2】並び替えUIの改善（既存機能の修正）

## 2-1. SPはドラッグをやめて▲▼ボタンに

スマホでドラッグ&ドロップが実用に耐えていません（長押しでブラウザのコンテキスト
メニューが出る／ハンドルが小さすぎて掴めない）。**SPのみ**、ボタン式に変更します。

- **PCはドラッグ&ドロップのまま**（問題なく動いているため）
- SPは `Reorder Buttons`（`616:8183`）に差し替え
  - **丸ではなく長方形**（34×26を2つ縦に重ね、全体34×54）。タップ領域を稼ぐためです
  - 上下端のみ角丸8、内側は2。ひとつながりの操作単位に見せています
  - 先頭行の▲、最終行の▼は**無効状態**（`text/secondary`＋不透明度40%程度）にしてください
- 差し替え済みコンポーネント:
  - `Admin Menu Row (Mobile)`（`418:463`）… メニュー管理
  - `Category Row (Mobile)`（`429:2534`）… カテゴリ管理
  - `Best Seller Row (Mobile)`（`619:862`）… ベストセラー設定

**実装上の注意**: 長押しでコンテキストメニューが出る問題は、ドラッグをやめれば
解消するはずですが、念のため並び替え領域に`touch-action`や`user-select: none`が
必要かどうか実機で確認してください。

## 2-2. 絞り込み時だけ並び替えできるようにする（挙動の整理）

現在は逆の挙動（カテゴリで絞ると並び替え**不可**）になっていますが、これを**反転**させます。

| 表示状態 | 並び替え |
|---|---|
| 「すべて」表示 | **並び替えUIを非表示**（ヒント文言も出さない） |
| カテゴリで絞り込み中 | **並び替え可能** |
| テイクアウトで絞り込み中 | **並び替え可能**（現状どおり） |

理由: トップページはカテゴリごとに横並びで表示されるので、店舗側が本当に調整したいのは
「そのカテゴリの中での並び」です。全商品を横断した通し順を触る場面がありません。
「すべて」で並び替えを許すと、80品の中から目的の2品を隣接させる操作になり非現実的です。

- **`display_order`の扱いは現行のまま**（グローバルな単一列）で構いません。
  絞り込み中の並び替えは「掴んだ行をドロップ先のグローバル位置へ移す」だけなので、
  他カテゴリの相対順序は保たれます（テイクアウト統合のときと同じ考え方です）
- **カテゴリ管理の画面にも同じルールを適用**してください
  （カテゴリ管理は一覧が常に全件なので、こちらは常時並び替え可能で問題ありません）

## 2-3. ヒント文言

Figma側は更新済みです。実装も合わせてください。

| 画面 | 文言 |
|---|---|
| メニュー管理 PC | `⠿ をドラッグして並び替えると、メニュー画面での表示順が変わります` |
| メニュー管理 SP | `▲▼ で並び替えると、メニュー画面での表示順が変わります。編集ボタンから表示・非表示の切り替えができます。` |
| カテゴリ管理 PC | `⠿ をドラッグして並び替えると、メニュー画面での表示順が変わります` |
| カテゴリ管理 SP | `▲▼ で並び替えると、メニュー画面での表示順が変わります。` |

「すべて」表示中はヒント自体を出さないでください（並び替えできないため）。
